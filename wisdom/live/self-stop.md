# Live self-stop (execute host lifecycle)

The configured agent can call `live.stop()` from `execute` to end its own active voice session. This is a host action over the same private execute IPC bridge and extension event bus used for other current-session host work. It is not a provider tool or a Realtime protocol event. It needs no new permission prompt: the current configured agent can already stop Live from the terminal. The host checks the captured session ID, file and branch leaf against the active Live run, so an old tool call cannot close another session's voice.

The hook takes no options. To stop an exact background job, use `jobs.stop(id)` separately, with the existing delegated-job confirmation. `live.stop()`, ordinary voice interruption, provider failure and `/live stop` do **not** cancel agent work. GPT-Live delegation keeps using the configured agent and its existing permissions, not a fake Realtime function-call protocol or an extra coding agent.

Live immediately invalidates playback/input callbacks and aborts capture; the host waits for provider socket close (including GPT-Live's bounded session.closed deadline), native audio stop and audio close before replying. Result: `{stopped: true, errors: [], jobsUnchanged: true}` only after observed teardown. If no matching voice is active, or teardown fails, `stopped` is false with bounded error labels; no raw device/provider errors or false success. GPT-Live transport exposes close timeout/close failure through `closeError`; final usage is still unknown on a timeout. Concurrent audio and socket close limit extra mic capture time. If audio launch has not completed, the hook explicitly reports that teardown is not yet observed; the late launch is closed on arrival. Google and OpenAI Realtime socket-close exceptions are reported as sanitized failures too. This is a local teardown guarantee, not proof of physical OS speaker drain or provider final usage.

Offline tests cover scoped self-stop, delayed audio stop, failure reporting, GPT-Live close timeout and provider regression. No paid provider or device was exercised. The worker IPC helper must forward `live.stop` with `{}` to the execute extension's new handler; it is owned by the job-bridge worker and is not part of this change.
