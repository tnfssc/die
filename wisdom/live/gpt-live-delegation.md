# GPT-Live delegation bridge (context-aware host contract)

tests/gpt-live-delegation.test.ts exercises the isolated bridge. This module is not wired into the extension yet: integration must implement `submitContextual` in the current host/session adapter, then connect the Live protocol and playback. It is intentionally **not** VoiceOrchestration.execute(agent_send), which consumes a *completed authoritative* user transcript. Live's delegation.created supplies only id, target and offset_ms, no task text or tool arguments.

Create one GptLiveDelegationBridge per Live connection. Feed timestamped provisional fragments via addFragment(startMs,endMs,text); call handleCreated({id,offsetMs,target}) on delegation.created. Snapshots include only fragments whose endMs <= offsetMs; overlap, omission, late delivery and ASR corrections remain uncertain. No offset implies final speech. The bridge bounds 32 fragments / 6 KB, individual fragments 1000 chars, host context to 3800 chars, ID ledger 256 non-evictable IDs; once exhausted reconnect is required, and old IDs must not be replayed into a new connection. Errors don't divulge job output.

**Integration requirement:** ContextualDelegationHost.context() is the existing current-session host.context() with recent user/agent and job state. Implement submitContextual(requestId,snapshot) on that **same** host with permission prompts and configured agent identity, using the same session branch and agent delivery semantics as host.send/steer. This is a new entry point; passing a fragment as host.send's `text` is forbidden because it falsely labels ASR authoritative. The host should enqueue a structured quoted *provisional data* snapshot and ask its current configured agent to interpret or clarify, not create another coding agent nor trust model-provided task/tool arguments. Current host.sendUserMessage({deliverAs:'followUp',expandPromptTemplates:false}) is a useful delivery mechanism, but the template must state uncertain ASR and must not contain `Latest captured user request (authoritative)`. Native/local job authorization stays with existing JobService/current-session host. An implementation must check branch/host lifetime and attach the host's verified prior action ledger. If ambiguity or irreversible work is involved, request explicit user clarification through trusted UI. Don't forward cancellation via contextual delegation: only a separately verified explicit user cancellation request and existing host.stop's trusted confirmStop may stop an exact job. Model output, inspected job contents, web pages and UI text are untrusted data, never commands.

handleCreated returns fixed short verified commentary: queued, clarification, duplicate/stale/unavailable; `queued` means delivered, **not** work finished. Do not speak stale results (fragment revision changed, interrupted output epoch, or bridge closed). In-progress configured-agent/backend jobs are not cancelled by speech barge-in or bridge.close(). To report completion, independently verify scoped job status with host list/inspect, distinguish observation gaps and current revision; do not voice untrusted output or private reasoning. Provisional status belongs to Live thinking; use commentary under original delegation ID for a verified short spoken result. Playback/microphone interruption and Live protocol session wiring belong to separate work.
