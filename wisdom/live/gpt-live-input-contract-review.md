# GPT-Live delegated input: independent contract review

Scope: read-only review of current source and protocol notes. No session identifiers, raw metadata, or implementation changes.

## Findings and blockers

1. Current extension sends the *entire* bounded snapshot as a visible user turn: `src/live/extension.ts:448-477` concatenates all retained fragments then sends a policy prefix plus `JSON.stringify(snapshot)` to `owner.delegate`; `src/live/main-owner.ts:430-469` calls ordinary `session.prompt`. `src/live/gpt-live-delegation.ts:133-146` includes every retained fragment ending before the delegation offset, without selecting new speech. A completed earlier coding request can thus appear actionable again. Hiding passive transcript bubbles (`src/live/main-owner.ts:539-552`) does not hide this user turn.
2. Do not treat a last fragment, silence gap, or offset as final ASR. The transport exposes provisional timestamped deltas and delegation ID/target/offset only; it supplies no task text, reliable turn boundary, finalized transcript, correction ID, or server truncation (`src/live/gpt-live-session.ts:1-38,60-65`; `wisdom/live/gpt-live-implementation.md:13,21`). Bridge retains arrival order, filters end <= offset, bounds retention and records omissions (`src/live/gpt-live-delegation.ts:65-101,113-143`). Overlapping fragments, late correction, omission, and cutoff must stay uncertain.
3. Prior user history is context, not renewed authorization. In the example, the initial coding request is already completed and the intermediate follow-up processed; only the latest short thanks/stop phrase is a new candidate. Earlier content can inform what “stop” refers to, but must not be issued as a second instruction. Approximate context clocks do not establish speech finality (`src/live/gpt-live-delegation.ts:65-78,129-143`).
4. “Thanks, stop” after completed work plausibly means end voice, not cancel all jobs. Do not automatically call `jobs.stopWork()` or demand blanket confirmation. Clear voice-off calls `live.stop()` and checks its result, preserving jobs; genuinely ambiguous voice-versus-work intent warrants a short targeted question. Explicit work stop uses existing trusted cancellation/report path; explicit both stops voice first (`src/session/host.ts:315-323`). Barge-in alone is not cancellation (`src/live/gpt-live-delegation.ts:104-107`).

## Minimal delivery contract

Deliver one concise ordinary user-facing candidate containing *new* speech, with only necessary conversation context. Do not place snapshot JSON, IDs, offsets, serialized host context, or generic policy sermon in the user message. Retain bounded internal evidence, uncertainty, host permissions, branch checks, ID deduplication, and canonical history. Selection/admission must remember previously consumed speech across delegations separately from retained transcript history; a later delegation does not reauthorize buffered old fragments. Late corrections can revise understanding, not silently duplicate irreversible work or suppress a fresh suffix. When a boundary cannot be established, ask a targeted repeat rather than fabricate completed speech. Transcript idle grouping is presentation only (`wisdom/live/gpt-live-transcript-grouping.md`). `queued` denotes dispatch, not completion (`src/live/gpt-live-delegation.ts:145-157`).

## Offline acceptance tests

1. Three timestamped groups: completed coding request, processed “anything else?” follow-up, latest “thanks, stop”; late delegation after all three. Assert one newly delegated user turn only about the latest speech, not old work as imperative. Assert no `delegationId`, `hostContext`, `offsetMs`, serialized fragments, or “Clarify ambiguous or irreversible requests” prefix visible/model-facing. Voice-off does not cancel work by default; genuinely unclear target yields specific clarification.
2. Delegate again with no new speech: no replayed action. New speech and new ID: fresh suffix only actionable, prior topic optionally labeled as context. Duplicate ID never dispatches twice.
3. Late correction overlapping older speech plus later fresh suffix; retain uncertainty and fresh speech without rerunning old work. Exercise omitted rolling history, fragment spanning cutoff, and missing/overlapping fragments: no speech after offset, false finality, or empty generic pseudo-command.
4. Run paired-owner integration, not just mocked bridge: Pi user turn clean, passive `live-transcript` non-turn/hidden, backend branch/permissions unchanged, completion custom messages non-user, and scoped dispatch/completion feedback truthful. Current `tests/live-extension.test.ts:1372-1421` merely checks that delegated text contains a phrase and misses the regression.

Block integration if old completed work is newly authorized, delegated turn still exposes raw snapshot/policy prefix, or provisional speech is presented as final ASR.
