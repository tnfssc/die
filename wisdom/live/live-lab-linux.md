# Linux Live Lab native helper baseline

Build: scripts/build-live-lab-linux-helper.sh (optional output path argument). Requires Linux, C++17 clang++ (or CXX), pkg-config, development packages libpulse, webrtc-audio-processing-1 (tested 1.3), json-c, glib-2.0. Runtime binary dynamically links libpulse, libwebrtc_audio_processing, libjson-c, libglib, C++ runtime and needs a running PulseAudio-compatible server (including PipeWire's pulse server). Not a dependency-free binary. --help and --self-test open no devices; self-test checks only build/load.

Protocol: newline JSON v1. hello before devices; start connects both streams asynchronously, initializes WebRTC APM echo canceller and noise suppression and emits ready only after both Pulse streams are ready, before any capture. play accepts base64 PCM16LE mono 24kHz, generation initially 0; emits played queuedMs including estimated Pulse render latency, with periodic drain updates and a final zero. flush requires a strictly increasing generation, discards queued playback, requests a Pulse stream flush and reinitializes APM. stop disconnects streams and emits stopped; Pulse I/O is nonblocking in a single 2ms event-loop pump (no blocking pa_simple read/write/flush or unbounded join). Device loss emits a fixed sanitized error; stop remains bounded. capture emits base64 PCM16LE mono 16kHz, 20ms/640 bytes. Playback ring is fixed at one second/24000 samples; overflow rejects the whole chunk with playback_full. Each actual 10ms rendered output block, including silence, feeds a band-limited 24k->16k APM reverse stream in the same audio pump as mic processing. APM delay uses Pulse stream latency estimates, not hardware timestamps. Captured samples are never silently dropped: internal overflow or stdout backpressure terminates the session. Stdout writes serialize whole JSON frames (retrying partial writes) with a 200ms backpressure deadline, then exit 74 on failure; do not treat a short/partial frame as recoverable. Stdin commands capped at 100KB. Bounded Pulse output buffering (~40ms) and a fixed 1s playback queue bound memory, but queue depth includes Pulse's estimate, not a measured acoustic path. APM echo cancellation and resampling need real hardware listening/latency acceptance before claiming speech quality or echo suppression.

Choose isolated devices with --source SOURCE --sink SINK, or LIVE_LAB_SOURCE/LIVE_LAB_SINK; omitted values use default Pulse routes. Names are passed directly to libpulse, never to shell. Avoid start without explicit args if physical hardware must remain untouched.

Device-free: python3 native/live-lab-linux/tests/protocol.py dist/live-lab-audio-linux and python3 native/live-lab-linux/tests/backpressure.py dist/live-lab-audio-linux. Isolated running-daemon test: native/live-lab-linux/tests/virtual.sh creates two unique null sinks, explicitly chooses one monitor as mic and the other as output, injects synthesized input, tests capture/play/flush/queue drain/stop/restart and bounded stop after removing a virtual source (Pulse may reroute it), unloads both modules by ID also on failure. Requires pactl and running server; never changes default routes or starts services. Null sink has no real speaker acoustic echo path, so test proves WebRTC APM processing call path and real virtual capture, not acoustic suppression quality. No physical microphone or speaker opened. Parent handles platform resolver and SDK/device acceptance.
