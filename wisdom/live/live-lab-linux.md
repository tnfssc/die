# Linux Live Lab native helper baseline

Build: scripts/build-live-lab-linux-helper.sh (optional output path argument). Requires Linux, C++17 clang++ (or CXX), pkg-config, development packages libpulse-simple, webrtc-audio-processing-1 (tested 1.3), json-c, glib-2.0. Runtime binary dynamically links libpulse-simple/libpulse, libwebrtc_audio_processing, libjson-c, libglib, C++ runtime and needs a running PulseAudio-compatible server (including PipeWire's pulse server). Not a dependency-free binary. --help and --self-test open no devices; self-test checks only build/load.

Protocol: newline JSON v1. hello before devices; start connects source/sink, initializes WebRTC APM echo canceller and noise suppression, starts threads, emits ready. play accepts base64 PCM16LE mono 24kHz, generation initially 0; emits played queuedMs. flush needs strictly increasing generation, drops queued playback, flushes Pulse output and reinitializes APM without a process restart. stop closes streams and emits stopped. capture emits base64 PCM16LE mono 16kHz, 20ms/640 bytes. Error codes/messages are fixed safe strings. Playback ring fixed 1s/24000 samples; overflow rejects the whole chunk with playback_full. Render includes silence in 10ms blocks, feeding 16kHz resampled actual outgoing PCM into APM ProcessReverseStream. Input calls ProcessStream every 10ms, setting stream delay using Pulse-reported record and playback latency; mic stays on while playback runs. stdout nonblocking: drops capture on pipe backpressure; control events get a bounded 100ms retry. Stdin command capped at 100KB. APM delay is an estimate, not hardware timestamps: tune/test real acoustics before claiming echo effectiveness.

Choose isolated devices with --source SOURCE --sink SINK, or LIVE_LAB_SOURCE/LIVE_LAB_SINK; omitted values use default Pulse routes. Names are passed directly to libpulse, never to shell. Avoid start without explicit args if physical hardware must remain untouched.

Device-free: python3 native/live-lab-linux/tests/protocol.py dist/live-lab-audio-linux. Isolated running-daemon test: native/live-lab-linux/tests/virtual.sh creates two unique null sinks, explicitly chooses one monitor as mic and the other as output, injects synthesized input, tests capture/play/flush/stop/restart, unloads both modules by ID also on failure. Requires pactl and running server; never changes default routes or starts services. Null sink has no real speaker acoustic echo path, so test proves WebRTC APM processing call path and real virtual capture, not acoustic suppression quality. No physical microphone or speaker opened. Parent handles platform resolver and SDK/device acceptance.
