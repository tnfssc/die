## Follow-up after v0.8.1 Ghostty mic-check [audio_start] (2026-09-24)

Known: v0.8.1's `audio_start` is assigned before attach/connect/tap/start, so it cannot distinguish these operations; catch discards the caught Error altogether. Authorization reached `open()` (permission denial has another code), but no TCC prompt + earlier SoX success does **not** prove this helper's TCC identity or route is fine. Linux helpers have separate audio_start paths, irrelevant to the reported Mac run. Do not claim a particular OSStatus or device was observed: none was supplied.

Evidence: Apple's [Using Voice Processing sample](https://developer.apple.com/documentation/avfaudio/using-voice-processing) (download `UsingVoiceProcessing.zip`, `AVEchoTouch/AudioEngine.swift`) enables input voice processing, connects its mixer explicitly to output using a voice-I/O format, installs input tap, then prepares/starts. Our code previously derived source rate from the *unconnected mixer's* output format and relied on its implicit output connection. Now derive the source rate from the voice-processing output node input format, connect mixer to output explicitly before attaching/connecting source, then tap/start; setup stage codes isolate output wiring, source wiring, tap and engine start. This is a plausible graph/format fix, not proven cause on Ghostty. Apple sample is iOS-focused; actual macOS device proof and compilation still pending parent Mac CI.

The caught Swift Error is bridged to NSError but only bounded ASCII domain and signed numeric code travel as structured fields, never localizedDescription, userInfo, raw device names or stderr. JS validates again and displays only these safe fields plus a known stage; malformed fields are dropped. Native Swift can throw at voice processing/start and synthetic guards; AVAudioEngine attach/connect/tap may instead raise Obj-C exceptions, which Swift catch cannot intercept. No permission resets, paid API or hardware test. Linux Bun focused tests, UI regression, TypeScript check and source ordering guard pass; these do not establish Mac compilation or live audio. Keep the older `audio_start` diagnostic for older bundled helpers. Parent must run Mac CI/build and publish later, no release here.

Release review tightened NSError domains to known system/synthetic domains in Swift and both JS boundaries: syntax/length alone could forward an arbitrary token-shaped domain. Unknown domains are omitted. Regression covers `SECRET_TOKEN_123`; numeric values remain signed 32-bit. Parent formatting fixed pre-existing worker formatting drift. Final focused suite: 47 pass, 0 fail, 424 assertions across 8 files; TypeScript check passed under Bun 1.4.1. Source ordering checks are not AVFoundation execution proof.
