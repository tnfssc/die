# Live as main orchestrator: offline runtime investigation

Scope: source + offline disposable probe only. No provider, microphone, real jobs, install or release. Read wisdom/values.md, wisdom/live/session-host-boundary.md, wisdom/live/scoped-execute-controls.md and wisdom/live/transcript-handoff-gap.md first. Probe: tests/live-main-orchestrator-runtime.probe.ts.

## Existing paths (source evidence)

- Normal entry src/cli.ts installs disk-backed session manager before importing Pi main, runs withDieSystemPrompt(cliArgs), registers die-tools + live extension factories. src/system-prompt.ts selects Die base according to CLI/project/global SYSTEM.md precedence. src/prompts.ts builds identity + execute guidance. Pi assembles append/context/skills/cwd/tool descriptions; src/agent/extension.ts before_agent_start augments assembled prompt with collaboration + role guidance, respecting user custom root prompts. session_start sets active tools to execute. Copying a base string into Live is not the same per-turn prompt/instruction frame.
- src/typescript/extension.ts registerExecuteTool registers actual Pi tool definition, parses parameters, scopes foreground shutdown/abort, invokes executeIsolated with cwd, session file, invocation ID and bridge handler, formats results. src/typescript/execution.ts spawns --die-internal-execute with stdin/image pipe and optional IPC job pipe; src/typescript/runner.ts transpiles/evaluates TS and installs job globals; src/typescript/job-bridge.ts transports framed requests/responses/ACKs and cancellation diagnostics. Nonzero exit, timeout, cancellation or image failure become thrown tool errors, not returned isError values. Success includes text/details/artifact metadata. src/agent/extension.ts supplies bridge handler: history/goals, JobService.handle for shell/subagent/jobs and host-confirmed stop; typescript/extension.ts handles handoff/live.stop.
- Tasks belong to TaskManager/JobService created in agent extension for the owning Pi context. src/agent/extension.ts completion batch sends Pi sendMessage with deliverAs steer + triggerTurn true; idle agent_end can hold turn for pending work; T3 native commands use a separate durable outbox. src/job-delivery.ts and bridge ACKs protect response/completion order. Live provider responses alone do not receive those notifications.
- Live extension obtains SessionHost through shared event bus in src/session/host-access.ts. src/live/orchestration.ts advertises six host tools (session_context, agent_send, agent_steer, jobs_list, jobs_inspect, job_cancel), not execute. src/session/host.ts pins manager/session/leaf, checks active ownership, deduplicates request IDs, gathers branch-only transcript, sends/steers via Pi sendUserMessage and gates cancellation with trusted confirmation. This is a companion-to-main queue, not main ownership.

### Offline follow-up (matching build, isolated real job)

Built this worktree's CLI with Bun 1.4.2 using `bun scripts/build.ts --reuse-web --outfile=dist/die-probe`. To avoid writing to symlinked main assets, the existing checkout's `dist/die-web` was copied into this worktree's ignored `dist/die-web` first; the resulting archive and executable are private to this worktree. Ignored `node_modules` and `runtime-assets` symlinks were only read, with no installs. Ran `DIE_PROBE_EXECUTABLE="$PWD/dist/die-probe" bun test ./tests/live-main-orchestrator-runtime.probe.ts`: **2 pass, 0 fail, 22 assertions**. The binary and tested registration source now match this worktree; the reusable web asset copy originates in the existing checkout.

The synthetic voice adapter now takes its declaration name and JSON schema directly from registered `execute` (including `outputByteLimit`), rather than spelling a narrower fake schema. This does not demonstrate any provider accepting that schema. The original fake subagent experiment remains in the first test for comparison; it does not launch a worker.

The second test wires registered execute -> compiled child TS runner/IPC -> **real TaskManager and JobService** in a disposable synthetic session/context. A harmless local shell fixture (`sleep 0.3; printf abcdefghij`) returns with `background: true` and a running command ID from `waitSeconds: 0`; after manager completion, a separate execute call uses `jobs.inspect` and sees the output. A direct service inspection checks a five-byte page (`abcde`, `hasMore`, `nextOffset: 5`); thrown runner errors propagate. The `outputByteLimit: 100` check confirms capture-limit reporting; it **does not** bound the formatted tool response to 100 bytes (a preliminary assertion for that failed: 2166 serialized bytes), so voice response-size policy remains open. No provider/model child, active user jobs, installs, or production session were involved. Only test-created fixtures are stopped/removed.

**Limit:** this is not production main ownership, Pi completion routing, or permission UI. It neither admits a Live voice call into the owning Pi session nor tests background delivery to that Live turn. Provider acceptance, prompt parity, and structured voice result size are still unknown.

## Real integration seams (not implemented)

1. One session/main owner across speech and text. Either make Live Pi main turn transport or safely expose owner session's tool dispatch + prompt lifecycle. Calling executeIsolated alone with a new handler does not confer parity. Bind admitted calls to manager/session ID/leaf/tool-call ID/shutdown signal; do not allow stale Live runs to use changed contexts. Keep explicit permission/stop confirmation; voice close must not cancel admitted jobs automatically.
2. Send provider the effective per-turn Pi-assembled prompt, tools and current branch messages (custom SYSTEM.md precedence, extension modifications, role/instruction frames, compaction), not dieSystemPrompt() alone. Need supported Pi prompt snapshot/turn adapter or shared prompt builder; check token/schema mapping per provider. Current voice transcript entries are not Pi tool-call history.
3. Dispatch voice tool calls through same registered execute tool with real context and extension bridge handler. Return structured bounded outputs/errors/images/artifact references; preserve handoff semantics and duplicate/reconnect write protection.
4. Deliver job completions and attention through shared session turn scheduling/IPC mailbox to Live-main continuation (and text fallback when audio unavailable). Current Pi sendMessage targets configured text agent; replacing agent_send alone loses background completions. Test resume/branch changes, compaction and artifact ownership.

Unknown: provider acceptance of execute schema/result size, stable Pi assembled-prompt/turn API for realtime, permission UI, actual job completion delivery and shared history. Separate controlled integration needed.
