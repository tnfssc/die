# Linux Live Lab acceptance (opt-in)

From repository root, install project dependencies with `bun install --frozen-lockfile` and build the real helper with `bash scripts/build-live-lab-linux-helper.sh` (build headers and libraries: [live-lab-linux.md](live-lab-linux.md)). Then run `bash scripts/live-lab-isolated-audio.sh`. The helper can be overridden with `DIE_LIVE_LAB_HELPER=/absolute/path/to/helper`. Requires Bash, PipeWire (`pipewire`, `pipewire-pulse`), WirePlumber with the stock `/usr/share/wireplumber/wireplumber.conf` policy profile, `pw-dump`, `pactl`, `parec`, `pacat`, `python3`, `bun`, `mktemp`, `timeout`, `ps` and `tr` (plus basic coreutils). There is **no pulseaudio executable requirement**. Only paid mode additionally needs `espeak-ng` and `ffmpeg`.

The wrapper creates private mode-0700 runtime/config/state/cache directories and a private PipeWire native socket, PipeWire-Pulse socket/cookie and WirePlumber `policy` profile. This profile excludes ALSA, Bluetooth, video and MIDI hardware monitors; the pre-test graph must have *only* Dummy-Driver and Freewheel-Driver nodes and no sinks/sources. Any other node fails before the test. It uses copies of packaged PipeWire configs (not user configuration), disables Pulse restore/always-sink modules and points DBus at a nonexistent **private** socket. No host services, default routes or configuration are changed. The wrapper traps termination and removes only its own processes and temporary directory. Do not bypass graph checks to get a green result. The TypeScript harness refuses a direct run without the wrapper isolation flag; do not point it at the desktop server.

Fixture mode injects fake SDK/provider output into `VoiceSession`; actual `PlaybackScheduler`, `LiveLabAudio`, native helper and private Pulse server carry the PCM. It scores the 830 Hz *tail* of a locally synthesized turn from the virtual output monitor in memory (not from queue depth). It then queues audible old-epoch 1130 Hz audio, interrupts, queues new-epoch 670 Hz audio, verifies the new marker reaches the monitor and the stale marker does not persist after the new epoch. Capture also continues. This establishes real virtual-output signal delivery and interruption, **not** acoustic output, microphone performance or AEC quality. Ordinary tests do not invoke this script.

Both native explicit streams start corked with DONT_MOVE. Before uncorking, the helper checks the server-selected device names and non-invalid indices; it emits ready before uncorking and never emits capture before ready. A mismatch fails closed. The harness additionally checks the JSON numeric sink/source indices of the helper's actual streams, monitor and optional injector before sending audio. Absence is retried briefly for registration; wrong indices are never accepted. No physical device is opened by this wrapper's graph.

Only after separate authorization, paid mode is `DIE_RUN_LIVE_LAB_ACCEPTANCE=1 bash scripts/live-lab-isolated-audio.sh --provider`. No paid call was made for this evidence. This branch loads the canonical credential, synthesizes local input using `espeak-ng` and `ffmpeg`, requires real provider transcripts, capture, turn completion, output and end-of-turn monitor correlation; it has a single session and bounded deadline without retries. Provider charges may apply. No audio, transcript or key is logged or written to repository files.

Evidence (Linux PipeWire 1.6.4, 2026-09-23): private graph reported `[('Dummy-Driver', None), ('Freewheel-Driver', None)]`; fixture succeeded with 830 Hz outputTail score 0.967, old-before-interruption 1130 Hz score 1.0, 670 Hz newEpoch score 0.814, and post-new-epoch old score 0.015. Capture continued and native queue drained. Previous desktop-server failure was described as policy rerouting from text `pactl` parsing, but that observation alone does not establish the root cause; the new JSON checks remove text-field ambiguity. A silent monitor or queue zero never proves rendered audio. No physical device was recorded or played to investigate the prior host failure.
