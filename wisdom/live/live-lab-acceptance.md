# Linux Live Lab acceptance (opt-in)

From repository root: 

1. Install a running PulseAudio/PipeWire-Pulse daemon and `pactl`, `parec`, `pacat`. Never run on an audio server where loading virtual modules is disallowed. No daemon is started and defaults are never changed.
2. Build the **real** helper: `bash scripts/build-live-lab-linux-helper.sh` (development headers listed in [live-lab-linux.md](live-lab-linux.md)).
3. After integrating `src/live-lab/playback.ts`, run `bun scripts/live-lab-acceptance.ts`. Optional: `DIE_LIVE_LAB_HELPER=/absolute/path/to/helper bun scripts/live-lab-acceptance.ts`.

Fixture mode injects only SDK/provider output into `VoiceSession`. `PlaybackScheduler` sends via `LiveLabAudio` into the actual native helper, explicitly connected to unique virtual `input.monitor` and `output` null sinks. `parec` records `output.monitor` (24 kHz PCM16) **in memory**; a scored final 830 Hz tone proves output was rendered after immediate generationComplete/turnComplete. It checks queue drain *and* final monitor signal, then flushes stale playback and confirms capture continues. This is a deterministic virtual-Pulse signal test, **not** provider, acoustic Mac speaker, or echo-cancellation quality proof. Ordinary tests never run this script.

Only after review, paid mode: `DIE_RUN_LIVE_LAB_ACCEPTANCE=1 bun scripts/live-lab-acceptance.ts --provider`. One session, 60s overall cap, no retries. It reads the existing canonical Live credential through `createDefaultLiveCredentialService().loadKey()` only in this gated branch. It synthesizes local speech with `espeak-ng`, converts locally with `ffmpeg`, sends it solely to virtual input, and requires real input and output transcripts, end-of-turn, audio, capture and output-monitor tail correlation. If transcripts are missing or no end-of-turn/audio arrives, it fails rather than claiming success. No transcripts, audio, keys, or SDK errors are logged or stored in repository files; output is booleans, timing and correlation only. Provider charges may apply. Never run paid mode as part of development or CI.

At startup the harness checks actual Pulse stream endpoints (not just requested device names) before feeding audio, because PipeWire session policy can silently reroute even explicit devices. A reroute is a hard failure rather than a false positive or accidental physical playback. This check applies to helper input/output, monitor, and the paid-mode speech injector.

On exit/failure/timeout the harness stops/kills its processes and unloads both modules by numeric IDs in reverse order. A 60-second timeout is bounded by subprocess timers; if the entire OS process is killed uncatchably (SIGKILL, power loss), use `pactl list short modules` to find leftover `die_accept_*` names and `pactl unload-module ID`. Run only with a working daemon; missing tools/daemon/helper are explicit failures. Virtual monitors do not exercise physical devices or establish acoustic quality.

Development evidence (Linux, PipeWire-Pulse, 2026-09-23): built with `bash scripts/build-live-lab-linux-helper.sh`; typecheck of harness reported no diagnostics against sibling scheduler source. `bun scripts/live-lab-acceptance.ts` was run in fixture mode only. This host's session policy routed the helper output to a non-virtual sink despite explicit `--sink`; before route verification the output monitor was silent (327680 PCM bytes, peak 0) even while 143 frames were sent and native queue drained. The fail-closed route check now rejects this condition *before playback*: `Helper output was routed away from virtual sink; refusing playback`. This host cannot produce a passing isolated-monitor result until its PipeWire policy allows routing to the virtual sink; no paid call was made. A zero native queue or transcript is not evidence of a rendered tail.
