# Live-lab playback scheduling

The provider can deliver seconds of 24 kHz mono PCM16 in a burst. Native stdin acceptance is **not** playback: the native ring holds roughly one second, and the old eager 200 ms writes could overflow it and cut off released replies.

Use `PlaybackScheduler` from `src/live-lab/playback.ts`. Construct with `send(frame, generation) => audio.play(frame, generation)`, `flush(generation) => audio.flush(generation)`, and a visible `onError` callback. Feed decoded PCM `Buffer` to `enqueue(buffer, playbackEpoch)`; call `start()` only after native reports ready. On model interruption call `interrupt(newPlaybackEpoch)`; on model turn completion call `turnComplete(currentPlaybackEpoch)` (the session's turn ID is **not** a playback epoch). Feed native played ring depth to `nativeQueued(ms)`. Call `close()` during teardown, before closing the helper. The scheduler starts at native generation 0 and expects strictly increasing interruption epochs. Audio from previous epochs is ignored, not logged. No native flush on normal turn completion.

The first complete 960-byte/20 ms frame can send immediately. Serialized writes refill a 60–80 ms wall-clock reserve rather than requiring 20 ms between writes. Timers wait for room in that reserve; elapsed time cannot accumulate more than 80 ms of refill credit after a stall. Native depth reports can increase the estimate but cannot lower it: reports have no write/epoch acknowledgement, so a delayed zero must not erase newly reserved frames. At a turn boundary a final even-sized short frame is sent too (not padded or discarded). Each response can buffer up to 2,880,000 pending PCM bytes (60 s); overflow reports an error once and rejects the remainder rather than silently trimming it. `state.pendingBytes` counts only **unsent** local bytes; `state.nativeQueuedMs` estimates native ring depth from native played reports and wall time, not audible acknowledgement. Provider-received bytes must not be presented as played. The scheduler permits subsequent turns while previous output drains. Native pipe writes may be in flight during interruption; generation flush gates all subsequent new-epoch sends, and old-epoch write rejection is expected and not a fatal error. Write/flush failures report errors and block playback until another interruption/teardown; callers should expose them.

Tests use an injectable monotonic clock and a fake writer, with no mic, native helper, SDK, credentials or paid traffic: `bun test tests/live-lab-playback.test.ts`.
