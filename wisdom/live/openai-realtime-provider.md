# OpenAI Realtime session seam (offline candidate, 2026-09-24)

Owns src/live/openai-session.ts and openai-resample.ts, not Gemini, UI, credentials, or native playback. Provider is wired into the current Live extension; Gemini remains default. 

GA WebSocket reference: https://developers.openai.com/api/docs/guides/realtime-websocket (Node example uses wss://api.openai.com/v1/realtime?model=gpt-realtime-2.1 with Authorization bearer header); https://developers.openai.com/api/docs/guides/realtime-conversations (session.update, audio/pcm input at 24k, output audio, server VAD, item truncate). Checked 2026-09-24. Latest name is evidence from the published example, **not** a guess that every account has access. No live provider/key test performed. The docs also describe a distinct /v1/live/sessions API: do not mix that protocol with GA Realtime events.

Contract: VoiceProvider keeps the existing single-use connect/sendAudio/endAudio/sendContext/close, state/generation/turn, and VoiceCallbacks. New optional getPlayedAudioMs returns the cumulative **played** PCM duration in the current playback epoch, read before onInterrupted flush; extension/native worker must supply it and reset it on epoch change. If missing, truncate at zero (safe but may erase heard text). Generated output is not heard output. Queue start offsets account for earlier generated items and clamp to generated duration. Server VAD speech start flushes queued audio immediately; server cancelled response does not duplicate the flush. Audio session uses native 16k microphone, streaming linear 16->24k converter with an end-of-stream held final sample, and native 24k PCM output unchanged. Context is only a labeled session-instruction observation, not completed user speech. Only completed provider input transcription associated with the latest committed item or a non-revoked response calls userTranscript; stale completion may still be displayed. Sensitive tool dispatch requires an item-associated final transcript, with a bounded wait rather than inferring intent from model tool calls. A queued agent result is not a completed job. Tool call_id is a lifetime dedupe key; only declared names dispatch; no retries for side effects. Bounded setup/tool timers, transcript/audio/context limits, and serial guards ignore late socket events. Session is not a reconnect or resumable conversation.

Limits: Bun 1.4.2 WebSocket bearer header was verified against a local loopback upgrade server (no external network), not the actual GA endpoint; fake sockets and typecheck cannot verify entitlement, acoustic speaker echo, model behavior, callback scheduling on device, or actual output transcription. Bun WebSocket headers are passed via a TS cast because the DOM constructor typing does not expose Bun's headers option. Earlier Mac speaker audit notes describe historical speaker self-interruption; subsequent playback, prompt, transcript and waveform fixes through e86c52a are preserved unchanged. Do not generalize that old symptom to the user's current installed candidate or claim new acoustic proof. No Mac install was performed. Existing values on truthful claims, evidence and whole-path testing apply; values.md unchanged.

Offline regression fixtures now cover GA transcript delta/done shapes, item-associated out-of-order ASR, response lifecycle and parallel tool continuation, cancelled tool events, and multiple queued audio truncation. Bounds on response/tool/item maps fail closed if an exceptional session never drains; provider entitlement, real-device acoustic timing, and end-to-end account behavior remain untested.

Integration follow-up: the extension treats OpenAI transcript callbacks as display/history only, not capture authorization. The provider associates completed ASR by item ID with the latest committed input frozen at response creation; it assumes the documented ordered single-socket/default-conversation VAD lifecycle (no out-of-band responses). Only the correlated current revision may authorize work. Sensitive tools can wait up to two seconds for that final ASR, then fail closed; duplicate final ASR does not re-grant consumed speech. Input display is completed ASR only, not incremental ASR deltas. Output deltas/final boundaries remain received model text, never verified heard speech; cancelled output is marked interrupted.

Tools recheck revision and close state in their dispatch microtask; already accepted jobs remain independent. Tool results are call-ID deduped and continuation waits for response completion and all results, once per response. Fresh speech suppresses old audio even before its first delta. Every queued unplayed audio item is truncated against the scheduler's conservative played-time estimate. A 1 MiB WebSocket send backlog fails closed rather than growing microphone memory indefinitely. Map/call caps bound the single-use session; no transparent reconnect/resume is implemented. Host context updates replace a bounded, labeled data observation in session instructions and do not themselves start an unsolicited response; results are available to the next model turn.

The 16→24 kHz adapter is deterministic streaming linear interpolation with exact rational phase and one held end sample. It is not a bandlimited mastering resampler; physical voice quality remains untested. Native device capture, output, processing and scheduling are untouched.
