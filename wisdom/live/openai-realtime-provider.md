# OpenAI Realtime session seam (offline candidate, 2026-09-24)

Owns src/live/openai-session.ts and openai-resample.ts, not Gemini, UI, credentials, or native playback. New provider is not wired into the extension yet. 

GA WebSocket reference: https://developers.openai.com/api/docs/guides/realtime-websocket (Node example uses wss://api.openai.com/v1/realtime?model=gpt-realtime-2.1 with Authorization bearer header); https://developers.openai.com/api/docs/guides/realtime-conversations (session.update, audio/pcm input at 24k, output audio, server VAD, item truncate). Checked 2026-09-24. Latest name is evidence from the published example, **not** a guess that every account has access. No live provider/key test performed. The docs also describe a distinct /v1/live/sessions API: do not mix that protocol with GA Realtime events.

Contract: VoiceProvider keeps the existing single-use connect/sendAudio/endAudio/sendContext/close, state/generation/turn, and VoiceCallbacks. New optional getPlayedAudioMs returns the cumulative **played** PCM duration in the current playback epoch, read before onInterrupted flush; extension/native worker must supply it and reset it on epoch change. If missing, truncate at zero (safe but may erase heard text). Generated output is not heard output. Queue start offsets account for earlier generated items and clamp to generated duration. Server VAD speech start flushes queued audio immediately; server cancelled response does not duplicate the flush. Audio session uses native 16k microphone, streaming linear 16->24k converter with an end-of-stream held final sample, and native 24k PCM output unchanged. Context is only a labeled session-instruction observation, not completed user speech. Only completed provider input transcription calls userTranscript. A queued agent result is not a completed job. Tool call_id is a lifetime dedupe key; only declared names dispatch; no retries for side effects. Bounded setup/tool timers, transcript/audio/context limits, and serial guards ignore late socket events. Session is not a reconnect or resumable conversation.

Limits: independent runtime reference still needed for Bun native WebSocket headers against the actual GA endpoint; fake sockets and typecheck cannot verify entitlement, acoustic speaker echo, model behavior, callback scheduling on device, or actual output transcription. Bun WebSocket headers are passed via a TS cast because the DOM constructor typing does not expose Bun's headers option. The existing macOS speaker audit finds headphones work and built-in output self-interrupts; source does not prove why. Do not call this fixed or install on Mac without consented real-path validation. Existing values on truthful claims, evidence and whole-path testing apply; values.md unchanged.
