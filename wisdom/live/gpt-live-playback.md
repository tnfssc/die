# GPT-Live bounded local interruption and automatic recovery

Native processed capture is PCM16LE mono16k,20ms/640-byte frames. Playback uses mono24k. GPT-Live helper uses unchanged PlaybackScheduler, caps pending PCM at9600 bytes/200ms plus its ~80ms native reserve and outstanding pipe write. Output is paced; overflow/write/flush errors are visible terminal faults, never silently resumed.

Local activity is an explicit limited acoustic heuristic, not validated VAD: four consecutive frames RMS>=0.032 (~-30dBFS) enter activity; fifteen below0.013 (~-38dBFS) end it. Qualified activity immediately flushes native/pending output and advances a LOCAL playback epoch. No mic gating. Drop output while active. Then require ten additional quiet20ms frames (200ms) before automatically accepting NEW arriving continuous output. Non-quiet input resets this guard; renewed sustained activity flushes again. Stopped capture cannot count as quiet. No timer/server acknowledgement/final transcript is treated as a remote response boundary.

Parent rejected the earlier strict mute-until-restart policy because it made normal live conversation unusable. Automatic local recovery is now implemented and tested, rather than requiring a new session after each utterance. No resetForFreshResponse API remains. API: start(), capture(pcm), output(pcm), close(); suppressed/suppressionReason/speaking/epoch expose local state, scheduler supplies pacing/feedback. Integration saves suppressed transcript deltas as “Voice (not played)” and resumes ordinary provisional transcript display after guard.

There is no deterministic old/new server output marker on this primary WS. A stale tail can be audible after recovery and a reply that starts during suppression may resume mid-sentence. Noise, echo and device processing can false-trigger; quiet speech can miss. Native processing is not proof of acoustic echo cancellation. Never call this perfect barge-in or validated VAD. [Official/dependency review](gpt-live-vad-review.md) documents concrete WASM/native/neural candidates and why no verified maintained drop-in was added; [implementation evidence](gpt-live-implementation.md) records tests and worktree.

Tests cover sustained onset/hysteresis, exact processed frames, pending flush despite outstanding writes,80ms reserve and delayed timers, speech/quiet guard drop, automatic same-stream resume, noise-reset/repeated speech, overflow and hard-error non-recovery. No paid/device tests; real-device echo/quiet-speech acceptance remains unrun.
