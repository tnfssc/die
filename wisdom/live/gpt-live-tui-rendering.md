# GPT-Live TUI delta flood: passive history is not a chat bubble

GPT callbacks in src/live/extension.ts emit a JSON `live-transcript` custom message for every provisional user/assistant delta. Pi's paired MainOwner.sendContext persisted them with `display: true`. Pi's interactive renderer treats **every displayed custom message** as its own chat component. Thus 24 streamed user deltas plus one voice fragment produced 25 `[live-transcript]` labels and 25 JSON payloads in terminal history, obscuring the real conversation. The bounded Live transcript widget was already readable and grouped the same fragments; it wasn't the cause.

The paired owner now uses `display: false` only for `live-transcript`. It still calls Pi `sendCustomMessage(..., { triggerTurn: false })`: full JSON/provenance remains in canonical session history and context, including user vs assistant role, uncertainty and playbackVerified=false, without falsely finalizing ASR/heard output or waking the coding agent. Other custom types keep their previous display behavior. Gemini and OpenAI Realtime transcript and owner paths are unchanged.

## Actual terminal proof

`tests/fixtures/live-gpt-tui.ts` injects fake GPT provider events and fake audio into the real Live extension, but uses the real MainOwner, source CLI, Pi session and Pi interactive renderer. In an offline 120×40 tmux PTY, select session-only trust, run `/gptflood start`. The fixture uses a unique command name to avoid overriding the production `/live` command. Captured **actual tmux pane histories** from before and after are in [before](evidence/gpt-flood-before.txt) and [after](evidence/gpt-flood-after.txt). The before capture temporarily restored the original `display: true` at the paired owner; after uses the committed fix. Before: 25 `[live-transcript]` labels plus JSON, alongside the useful `You: delta0 … delta23` and `Voice: provisional voice reply` widget. After: zero labels/JSON, both useful widget lines and Live status remain. No real provider, microphone, playback, or paid request was used. MISE warnings at pane start came from the shell's untrusted mise.toml, not Live.

Automated `tests/live-gpt-tui.test.ts` exercises the same PTY/fixture and inspects rendered terminal history, not just source; `tests/live-main-integration.test.ts` independently checks all 25 canonical passive Pi entries retain content and `display: false` without model turns. No-session PTY mode intentionally does not prove disk replay; integration exercises the actual session manager. This is a targeted TUI fix, not a policy change to other custom messages. Values #8 (truthful UI), #5 (bounded visible view without quiet history loss), #6 (passive speech does not authorize work), and #10 (durable proof) already cover the lesson; no values edit needed.
