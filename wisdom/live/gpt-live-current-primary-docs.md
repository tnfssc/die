**Backend freedom:** client delegation lets the application choose and run its backend (model/service, instructions, tools and routing). Responses delegation has a *different* function-result/response.create flow; it is not required for client mode. Keep the canonical configured coding agent as the executor.

**Wire and timing:** start with delegation type client. session.delegation.created supplies delegation.id, target and offset_ms, but no task text. Keep caller/assistant transcript deltas separately with start_ms/end_ms, saved conversation and current task state; provisional fragments can be late, uneven or wrong and offset does not certify a final user turn. session.output_audio.delta has no timestamps or output-done event. Local interruption can flush playback, not cancel backend work, nor guarantee that later server audio is a fresh turn. Maintain running job and speech state separately.

**Context/results:** use session.instructions.append only for trusted application instructions; session.thinking.append for factual background/progress; session.commentary.append for brief speech-relevant verified outcomes. Client delegation results can be returned directly under the observed delegation_id; report completed work only after backend verification. General context can use delegation_id:null. The corresponding *.appended acknowledgments match outgoing event_id through client_event_id and carry estimated timeline start_ms/end_ms: they mean context injection, NOT completed speech, playback, task, or guarantee of model use. Pending appends can remain unacknowledged if timeline stalls and may error at close. session.closed alone confirms finalized voice usage; transport failure or timeout leaves it unknown. No invented cancellation/result fields.
