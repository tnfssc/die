# Live tools in terminal transcript (2026-09-25)

Observed: src/live/main-owner.ts appends assistant toolCall and toolResult to the pinned Pi session manager and agent message array, in a serialized pair. It invokes registered execute and before/after hooks once. But direct appends do not emit Pi agent lifecycle events. Pi InteractiveMode creates its ordinary ToolExecutionComponent on tool_execution_start and completes it on tool_execution_end from AgentSession subscribers. Live extension widget displays voice transcript lines and state, not tool events or persistent chat transcript. The real createAgentSession offline test subscribed and received zero tool events before the fix despite a completed owner call.

Fix: at the existing Live main-owner tool pair, publish start/end to pinned AgentSession subscriber-only _emit seam. This uses Pi normal execute renderer without entering agent prompt/execution or firing extension hooks again. Start follows canonical assistant history append; end follows result append. End carries a separate terminal-only view capped at 4096 characters, with no voice-supplied code in args and only renderer-known details; original tool result/history/provider return stay unchanged. UI listener failures cannot change tool execution. Private Pi 0.87 _emit is a narrow compatibility dependency; replace with public external-tool UI events if upstream adds them. No parallel transcript store or redraw replay.
