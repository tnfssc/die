# GPT-Live primary WebSocket adapter evidence (2026-09-24)

Sources checked directly:
- https://developers.openai.com/api/docs/guides/voice-websockets?api=live — primary endpoint `wss://api.openai.com/v1/live/sessions` without query, Bearer key, first event `session.start`; startup session model/audio/voice/delegation; wait for `session.started`. PCM16LE mono 24 kHz input uses `session.input_audio.append` with base64 `audio`; output `session.output_audio.delta` with base64 `delta`. End with `session.close` and wait for `session.closed` before claiming finalized usage. The guide's later Realtime examples belong to a separate API tab.
- https://developers.openai.com/api/docs/guides/live-delegation?delegation-mode=client — startup `delegation:{type:"client"}`; `session.delegation.created` has `offset_ms` and `delegation:{id,type:"delegation",target:"client"}`; **no user utterance or task text**. Scoped `session.commentary.append` and `session.thinking.append` send `delegation_id` and `content`. Transcript deltas have `delta,start_ms,end_ms`; no turn-finished event, and timing is approximate.
- https://developers.openai.com/api/docs/guides/live-conversations — transcript fragments are provisional and may arrive unevenly; `session.closed` carries final cumulative voice usage.
- Official SDK types at https://raw.githubusercontent.com/openai/openai-node/master/src/resources/live/live.ts checked for event field names, optional event_id, required delegation_id, ErrorEvent type `error`, and session.closed usage.

Adapter: `src/live/gpt-live-session.ts` is single-use, independent of Realtime's VoiceProvider tool/completed-transcript guard. Consumer calls `connect(key)`, streams 16k mono PCM16LE via `appendMicrophone` (stateful 24k conversion), handles `onInputTranscript` / `onOutputTranscript` provisional fragments, `onDelegation` with ID/target/offset, `onAudio` 24k PCM, `onReady`, `onError`, and `onClosed(finalized,usage)`. App-authorized work returns through `commentary(id,content)` or `thinking(id,content)`. Duplicate IDs are ignored per session; never infer task text or authorization from offset. The host bridge MUST verify work, permissions, confirmed actions, and revisions separately; this adapter never calls Realtime tools.

Limits: mic frames <=3,200 bytes, socket send buffer <=192,000 bytes (fail visibly), event <=150,000 bytes, received PCM <=96,000 bytes per event and split into <=9,600-byte callbacks, <=256 delegation IDs, transcript <=4,096 chars, update <=512 chars, connect/close deadlines 15 seconds. Callback is synchronous: it does NOT implement a player, mic VAD, echo suppression or interruption epochs; integrator must cap and flush playback (100–250ms target), clear on local VAD and avoid assuming a server old/new audio boundary. The adapter by itself does not authorize delegated actions or prove playback parity. Never claim `session.closed` usage on abrupt transport loss. No paid/device/key tests.

Verification: fake endpoint `tests/gpt-live-session.test.ts` covers exact handshake, resolved model/delegation rejection, ready gate, continuous PCM, interleaved fragments and late correction, delegation dedupe/scoped updates, 200ms output chunks, buffer limit, malformed audio, error sanitization, abrupt close and finalized usage. Bun 1.4.2: 5 passed / 81 assertions; `tsc --noEmit` and diff check passed. No extension or native edits.
