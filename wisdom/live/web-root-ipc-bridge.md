# Root Pi web-voice IPC integration (2026-09-25)

The owning Pi extension installs a private FD3/FD4 bridge only when its spawn set the non-secret DIE_WEB_VOICE_FD=3 and DIE_WEB_VOICE_OUTPUT_FD=4 markers; the markers are deleted immediately. FD3 is an inbound anonymous pipe and FD4 is an outbound anonymous pipe supplied by the canonical upstream Pi RPC spawner, not a browser-supplied path or bearer credential. Child tools/agents must never inherit FD3 or FD4. No credential is placed in the environment or emitted on the channel. The channel is capability-scoped to one spawned Pi process and its current owning SessionHost; the upstream route must authenticate and bind its thread/generation before forwarding any frames. The private bridge does **not** itself authenticate a browser.

One-byte frame kind + uint32 big-endian payload length; kind 0 JSON control <=16KiB, kind 1 input PCM <=64KiB (bridge additionally caps each accepted input chunk to 3,200 bytes), kind 2 output PCM <=64KiB. Buffered outbound bytes <=128KiB; incoming incomplete frames <=128KiB. First message {type:'ready',protocol:1}. Server starts via {type:'start',provider:'gemini'|'openai',model?:string}; root responds started then {type:'status',state:'ready'} once connected. Server sends stop, mute with boolean, or interrupt; root returns error codes, closed status and PCM/interrupt events. Voice stop revokes lease and closes provider; it never stops coding jobs. Replacement and Pi session shutdown revoke; channel disconnect closes voice and channel. Async key resolution is generation checked, so a stop before resolution cannot start a provider. Keys resolve through canonical per-provider ModelRuntime on the Pi server only; OpenAI accepts stored API key, not OAuth. Provider factory uses real Gemini/OpenAI adapters; tests stub both to avoid paid calls.

Security limits: owning SessionHost lease gates voice delegation and never auto-confirms permission. A provider transcript is content evidence, not human identity or permission. This bridge alone does not prove browser authentication, route admission or real provider/microphone behavior. Upstream must implement FD3/FD4 anonymous-pipe spawn and authenticated route; lifecycle parent must aggregate root and CLI live.stop listeners and address pending-provider teardown. No paid call was made. Offline root tests cover both provider paths, malformed framing, stale credential result, replacement/stop/disconnect and jobs preservation.


Integration corrections: bridge now awaits relay.shutdown (lifecycle commit d834e9e), explicit stop returns a stopped acknowledgement only after verified provider teardown. Root session_shutdown awaits that stop; live.stop aggregates all matching CLI/web lifecycle owners and reports any failure without affecting jobs. SessionHost leases expose valid/onRevoke so host closure eagerly tears down provider authority, and bridge validates exact current host. Missing credentials use safe provider-specific UI errors. In-flight credential loads remain single-flight; retry during pending load returns visible start_pending rather than opening another provider. Root bridge fake tests cover both providers, sanitized credentials, canceled replacement and awaited shutdown. Canonical route must drain old output through stop acknowledgement before another browser may attach; no browser acceptance claimed by these unit tests.
