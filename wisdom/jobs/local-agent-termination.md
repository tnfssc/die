# Local agent termination ownership

Local `jobs.stop` uses TaskManager.kill: POSIX signals target the agent detached process group, not groups spawned later by that agent. The child CLI is launched via process.execPath with DIE_SUBAGENT_DEPTH and runs the tasks extension. The extension session_shutdown awaits TaskManager.shutdown for normal lifecycle transitions, but raw SIGTERM does not itself dispatch session_shutdown; the only explicit process SIGTERM handler found in our source is the web launcher backend-forwarding handler. Therefore a local CLI agent installs a SIGTERM bridge once its own TaskManager exists. It asks that manager to shut down its session-owned jobs before exiting 143. The bridge is removed on session_shutdown. Root sessions and native delegation do not install it. No shared task registry is introduced.

Evidence/limits: TaskManager.kill signals the owned subprocess group and escalates after its grace period; TaskManager.shutdown waits for direct child close events with a watchdog, then records closure-unobserved on timeout. This does not establish that descendants in independently detached groups have exited. The parent kill grace may kill the agent before its own shutdown finishes; SIGKILL, crashes and shutdown before extension/manager initialization cannot cooperate. Local fake tree/signal tests assert scoped request and ordering, not OS process-tree closure. No live process or signal acceptance was run for this change.
