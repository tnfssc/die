# CLI live architecture research — 2026-09-25

## Current CLI path

- `src/cli.ts` registers `src/live/extension.ts` as the hidden `die-live` extension. `/live` toggles start/stop; `/live provider`, `/live model`, `/live setup`, and `/live status` manage a voice selection independent of the coding-agent model. `src/live/status.ts:liveLocalOnly()` deliberately rejects non-TUI, non-TTY, SSH, web-launched, and subagent sessions. **The existing `/live` command is not a web entry point.**
- `src/live/providers.ts` selects Gemini `gemini-3.8-live` by default, OpenAI Realtime `gpt-realtime-2.1` or `-mini`, or the distinct `gpt-live-1` transport. `src/live/config.ts` persists selection in `~/.die/live-settings.json`.
- `src/live/credentials.ts:createDefaultLiveCredentialService()` reads canonical agent `auth.json` through `ModelRuntime`, without model-network refresh. Google accepts an API key obtained through that runtime; `~/.die/live.env` is **explicit import only**, guarded against replacing existing credentials. OpenAI requires a stored canonical `openai` API key—not `openai-codex` OAuth, a ChatGPT subscription, or ambient credentials. `/live setup` uses `src/live/setup.ts` for Google and `runOpenAISetup()` in `extension.ts`.
- `src/live/types.ts:VoiceProvider` is the reusable provider seam: `connect(apiKey)`, `sendAudio(base64)`, `endAudio()`, `sendContext(text)`, `close()`, with `VoiceCallbacks` for audio, transcripts, interruption, state, and error. `src/live/session.ts:VoiceSession` uses the Google SDK Live connection (16-kHz PCM input, 24-kHz PCM output); `src/live/openai-session.ts:OpenAIRealtimeSession` uses a server-side Realtime WebSocket, resampling the input to its 24-kHz format. `src/live/gpt-live-session.ts:GPTLiveSession` is **not** that Realtime protocol: it uses `/v1/live/sessions`, continuous PCM and provisional transcripts.
- CLI device transport is `src/live/audio.ts:LiveAudio`: a bounded, line-protocol native helper (`live-audio`/`live-audio-linux`) delivering 20-ms 16-kHz capture frames and playing 24-kHz PCM. `src/live/playback.ts:PlaybackScheduler` handles queue/flush generations; `extension.ts:Run` owns provider, helper, playback, UI, and startup order. It waits for helper hello and provider acceptance **before** starting devices. This native helper cannot capture a remote browser’s microphone.
- Agent work remains in the configured agent. `src/live/orchestration.ts:createOrchestration()` exposes `session_context`, `agent_send`, `agent_steer`, `jobs_list`, `jobs_inspect`, and explicitly confirmed `job_cancel`; it consumes captured completed speech rather than accepting model-written task text. `src/session/host-access.ts:getSessionHost()` obtains the owning `SessionOperations` from `src/agent/extension.ts`; `src/session/host.ts` owns scoped dispatch and observations. GPT-Live instead uses `src/live/gpt-live-delegation.ts` and `SessionOperations.delegate()` with a bounded, **uncertain** fragment snapshot—not purported final ASR. Host updates are observations, not evidence of task completion.
- Speech barge-in invalidates playback and pending speech authority; it does **not** cancel work. `/live stop` and `live.stop()` close voice, not jobs. `src/live/lifecycle-access.ts:stopCurrentLive()` requests the owning extension’s stop; `src/typescript/extension.ts` exposes it to `execute`. `Run.stopObserved()` aborts callbacks/capture, clears playback and UI, and awaits audio/provider teardown; it returns `{stopped, errors, jobsUnchanged: true}` rather than claiming success when teardown is unobserved. Stop access checks session ownership; explicit work cancellation uses `jobs.stop(id)` or `jobs.stopWork()` separately.

## Smallest viable **web** port

Start with **one provider, Gemini**, one active voice connection per authenticated web thread, and browser capture/playback. Reuse the **server-side** `VoiceSession`, `VoiceProvider`/callbacks, `createOrchestration`, credential service, and scoped agent-operation semantics—not `LiveAudio`, terminal rendering, or a direct browser-to-provider API key. Add a small authenticated, thread-scoped bidirectional audio/control socket in the web backend; keep keys and provider sockets there. In the browser use `getUserMedia`, an `AudioWorklet` for mono PCM conversion (16-kHz capture, 24-kHz playback), and a small start/stop/status control. Bound frames and queues; flush on the provider playback epoch. Get explicit microphone consent and handle permission denial.

The relevant **tracked** web integration is `integrations/t3/upstream/die.patch` plus `integrations/t3/build/build.ts`; `src/t3/web/launcher.ts` starts the packaged backend. Web UI/backend source paths referenced by that patch include `apps/web/src/components/ChatView.tsx`, `apps/web/src/components/chat/ChatComposer.tsx`, `apps/server/src/orchestration-v2/Adapters/`, and `packages/contracts/src/orchestrationV2.ts`. Those upstream source files are **not present as editable sources in this checkout** (`dist/die-web` contains built output); inspect the pinned upstream during implementation rather than editing generated `dist`. Add a typed socket contract at that web contract boundary and bind it to the existing authenticated thread/provider session. Do not invoke a CLI slash command over a terminal or create a second coding agent. In particular, verify how T3’s Pi adapter delivers a message to a **busy** thread before mapping `agent_send`/`agent_steer`: the CLI’s private extension event bus and `SessionHost` are not automatically accessible to T3’s web process.

For a first slice, defer GPT-Live, native-device forwarding, SSH, waveform, speaker checks, and cross-device reconnection. Add OpenAI Realtime afterward using the same server/browser audio boundary; its input rate, setup, VAD events, and error classification need separate tests. Do **not** silently treat GPT-Live as another Realtime model.

**Risks and checks:** thread-switch/disconnect must revoke old audio, tool authority, and callbacks without stopping agent jobs; repeated stop must be idempotent and report failed teardown. Never send API keys or raw provider errors to the browser. Test fake provider/audio sockets for ordering, frame sizes, backpressure, interruption flush, stale thread rejection, authenticated socket access, missing/OAuth credentials, busy-agent delegation, observed stop, and jobs remaining alive. Re-run existing `tests/live-*`, `tests/openai-session*`, and T3 contract/adapter tests. Finally test the built `die web` with real browser mic/speakers and an opt-in paid provider: offline protocol tests do not establish acoustic barge-in or the actual web experience.
