# Subagent workspace/setup — lead source verification
2026-09-21; research only.
Native subagent flow: root JobService -> die_task_launch -> DieTaskService.launch -> orchestrator.delegateTask async -> delegated_task.request -> makeSubagentChildThread. Launch has prompt/profile/clientRequestId, not workspace strategy/branch/setup fields. SubagentProjection.makeSubagentChildThread ~40 spreads parentThread, preserving parent branch/worktreePath. No fresh worktree is created: parent main checkout shared if no worktree, otherwise all children share same parent worktree.
Compare ThreadLaunchService: workspaceStrategy supports worktree/existing_worktree/root; provisioning branch path ~267-342 uses git worktree creation, updates metadata; ~393-453 invokes ProjectSetupScriptRunner.runForThread in resolved cwd before releasing prepared run, according to setup async/wait policy. Runner~349 selects setupProjectScript(resolveProjectScripts(settings,project)); no configured script => no-script. This launch path is NOT called by native delegation.
Thus 'spawn5 subagents' never auto provisions5 worktrees or runs project setup per child. Adding text 'separate worktrees' is a model instruction only, not workspace API. Model may manually shell git worktree add, but that bypasses T3 launch bookkeeping/setup triggers unless explicitly wired; not guaranteed behavior and no automatic per-thread cwd change.
Future implementation should add structured workspace strategy and route child preparation through T3-owned launch/setup pipeline with lineage/result ownership preserved, not merely manual git commands. No implementation changes authorized this question turn.
