## Release blockers

1. **Delegation is rejected before the selected coding model runs.** `main-owner.ts:423-430` invokes `session._runAgentPrompt(text)` with the Live owner still registered. `agent/instruction-continuity.ts:135-162` patches that very method to invoke `withOrdinaryMainTurn`, whose `main-owner.ts:93-103` rejects whenever `currentMainOwner(manager)` exists. The failed operation is cached under its ID (`main-owner.ts:416-438`), so retry with that ID cannot succeed. The owner test at `tests/live-main-owner.test.ts:524-550` replaces the method on the *instance*, bypassing the real prototype wrapper, and therefore misses the blocker. Add an integration test using the real wrapped method with an acquired Live owner and a stubbed agent/provider; assert an actual selected-agent turn succeeds and same-ID replay is idempotent. Keep ordinary independent prompts rejected during Live ownership; admit only an explicitly scoped, serialized delegation.

2. **Direct private invocation skips ordinary prompt setup, even if admission is repaired.** Pi's `AgentSession.prompt` performs preflight/extension command handling, `before_agent_start`, image normalization, creates a typed user message, injects pending next-turn messages, and prepares the system prompt/tool loadout before calling `_runAgentPrompt(messages)` (installed package `agent-session.js:1270-1331`). The private `_runAgentPrompt` only calls `agent.prompt(messages)` and settles/continues (`agent-session.js:1078-1105`). Passing a raw string here is outside the private method's declared `AgentMessage | AgentMessage[]` contract (`agent/instruction-continuity.ts:28,146`), and does not prepare a user message. Use the supported ordinary prompt pipeline (`session.prompt(text)` or equivalent public prompt seam) with a narrowly scoped admission capability for this owner and queued delegations. Preserve ordinary preflight hooks, selected tool/prompt policy, agent events, session persistence and errors. Test `before_agent_start`, policy/permissions, actual tool call, persisted user/assistant/tool entries and instruction continuity.

3. **No asynchronous backend feedback is sent to GPT-Live.** `extension.ts:429-442` acknowledges queueing, and on completion only sends generic `gpt.commentary(id, "...consult session history...")`. `main-owner.ts:423-438` never invokes `callbacks.onContext` for delegated output; existing `onContext` paths are initial history, explicit sendContext, and direct Live-tool context preparation (`main-owner.ts:359-360,459,690`). Thus `extension.ts:342-347` cannot forward selected-agent answer/tool/job updates to `gpt.observation`. Subscribe to the ordinary agent event/settlement stream, associate events with the delegation ID, project bounded tool/result/output/job updates into Live observations/commentary without replaying commands. Test delayed tool output and async job completion (and failure), not only queue acknowledgement.

Additional check: Live acquisition requires an execute-only loadout (`main-owner.ts:161-177`). Ensure delegation's ordinary pipeline restores the selected agent's intended tool policy instead of inheriting the Live-only execute restriction.
