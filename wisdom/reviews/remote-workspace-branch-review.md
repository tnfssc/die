## Findings / decision points

1. **P1 if presented as a shipping remote-workspace feature; not a defect in research scope** — `experiments/remote-workspaces/README.md:105-119`, `wisdom/remote-workspaces/ssh-research.md:1-28`. The demos prove target-directory execution in separate *local* processes, not SSH transport, remote authorization, dropped network/host restart or remote session persistence. Option A actual agent remains owned by the controller process; the separate viewer's departure is not controller/laptop failure. Option B suspends its scripted controller while the target shell keeps running. The documents state these limits honestly. Before claiming a product feature, choose remote full-agent vs local-agent/remote executor placement and run an explicitly authorized real SSH/disconnect/recovery test.
2. **P1 only if reused as a network service; intentionally out of scope for the local probe** — `experiments/remote-workspaces/runtime.ts:25-45,52-72,108-139,159-165`. The probe accepts arbitrary execute source/shell from anyone able to attach to its Unix socket; maps/status/IDs exist only in memory, 32-run limit is a count rather than an input/output-byte or durable-state cap, and abort/shutdown is not restart recovery. Its private temp-directory socket and trusted local fixture are sufficient for this demo, *not* authorization, resource or exactly-once semantics across SSH. A future service needs authenticated transport, bounded payload/status retention, session/job ownership, stable remote identity and acceptance-vs-reply reconciliation; never replay unknown mutating requests blindly.
3. **P2 documentation hygiene before using this as current integration guidance** — `wisdom/remote-workspaces/ssh-prototype.md:3-16,135-155`. The historical macOS worktree and “PR preparation”/PR creation blocker describe branch provenance, not a live PR or current develop. Mark those as dated history or update the handoff and base reference; do not use the parent-machine paths or the PR URL as a prerequisite for landing research.

No confirmed correctness failure in the bounded local probes. `runtime.ts:77-96` owns A's controller independent of attachments; `client.ts:18-20` detaches presentation only; B resumes explicitly in `demo.ts:144-155`. Explicit SIGTERM shuts down owned jobs (`runtime.ts:159-165`); `demo.ts:162-172` tears down its children and fixture, `rpc-agent-demo.ts:256-260` closes loopback/fixture. The latter tests the actual RPC agent with three deterministic fake-model turns, not provider reasoning or a production attach API. Limits and ownership are mostly called out already; do not turn prototype tradeoffs into false blockers for a research-only merge.
