# Herdr integration

When Herdr starts the root interactive pane with `HERDR_ENV=1`, `HERDR_SOCKET_PATH`, and `HERDR_PANE_ID`, die reports that pane's agent state over Herdr's local socket. It needs no config or installed Pi extension. Child workers do not report. Die finds them through `DIE_SUBAGENT_TYPE` or a positive `DIE_SUBAGENT_DEPTH`. Non-UI modes do not report either, even when they inherit Herdr's environment. A malformed depth counts as non-root.

The code is in `src/herdr-agent-state.ts`. It is a separate, type-safe adaptation of Herdr-managed Pi integration v8 at `~/.pi/agent/extensions/herdr-agent-state.ts`. That managed source stays read-only; die neither loads nor changes it. The adaptation keeps `pane.report_agent_session`, `pane.report_agent`, and `pane.release_agent`, along with monotonic sequence numbers and session path/ID refs. Locally installed Herdr 0.7.5 accepts any label for `agent`, but its built-in render and detection enum has `pi`, not `die`. Native die identity therefore does not work end to end. Reports use source `herdr:die` with compatible agent identity `pi` until Herdr documents native die support.

State comes from Pi lifecycle events, not from polling processes. `agent_start` reports working. `agent_settled` reports idle only when `ctx.isIdle()` is true. Blocking UI prompts and `herdr:blocked` custom events report blocked. Root-owned background jobs and subagents keep the pane working while they run, even after the foreground turn settles. If one completion starts another agent run, the normal event reports working again. Session reload, new, resume, and fork replace reporting authority without releasing the pane. Only quit shutdown releases it.

Socket failure is silent and does not stop die. Reports stay in wire sequence order. They use short bounded timeouts, retry once, and merge pending state. Startup reporting stays async. On quit, Pi waits for the same bounded drain before exiting. Pane, session, and blocked-message fields are cleaned and length-limited before sending.
